### BE-05 · Smoke test dua host (tanpa header `cf-mitigated` di semua respons)

| Request | be.aina.ai.id | workers.dev |
|---|---|---|
| GET /v1/plans, UA `curl/8` | 200 | 200 |
| GET /v1/plans, UA `badi-app (reqwest)` | 200 | 200 |
| GET /v1/plans, UA Chrome | 200 | 200 |
| POST /v1/auth/exchange `{}` | 401 JSON dari Worker | 401 JSON dari Worker |
| POST /v1/billing/midtrans tanpa signature | 403 Forbidden (cek signature Worker) | 403 |
| GET /v1/account tanpa token | 401 | 401 |
| GET /download | 200 | 200 |
| GET /ketentuan | 200 | 200 |

- Body `/v1/plans` di kedua host **identik** (md5 sama).
- Proxy website `https://aina.ai.id/api/v1/plans` → 200 (service binding tidak terganggu).
- POST ke endpoint Midtrans sampai ke Worker dan ditolak oleh pengecekan signature, bukan oleh WAF.
  Artinya webhook Midtrans asli akan bisa masuk lewat `be.aina.ai.id` (BE-11).

**Kesimpulan BE-05:** bypass rule tidak diperlukan. Pengecekan manual di dashboard (Bot Fight Mode, WAF)
tetap disarankan supaya ada catatan konfigurasinya. Lihat `BE-01-03-audit.md`.

### BE-06 · Cara melihat traffic per hostname
Dashboard → Workers & Pages → `badi-cloud` → **Logs** → filter/group by `$workers.event.request.url`
(atau host). Sampling 10%, jadi kalikan 10 untuk perkiraan jumlah total. Yang dibandingkan adalah
proporsi `be.aina.ai.id` vs `badi-cloud.faisalmashuri16.workers.dev`.

### BE-07 · Origin check
Dibuktikan lewat unit test. Origin `https://be.aina.ai.id` dan workers.dev diterima,
`https://evil.aina.ai.id` dan origin kosong ditolak. Secara live hasilnya tidak bisa dibedakan dari
luar tanpa sesi asli, karena keduanya mengembalikan 401 untuk token palsu. Tes dengan sesi asli masuk
BE-10.
